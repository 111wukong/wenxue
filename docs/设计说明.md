# 问学 · 设计说明

这份文档回答五个问题：

1. 应用的核心学习场景是什么
2. AI 功能具体以什么形式呈现
3. agent 集群怎么分工、怎么协作
4. 趣味性体现在哪些交互上
5. 关键功能模块与预期效果

---

## 一、核心学习场景

### 场景 A · 一对一讲透（solo）

一个考点从零讲起。老师按**五段结构**讲：

1. 严格表述 —— 完整定义，**包含全部前提条件**，一个都不能漏
2. 直观解释 —— 几何上或生活里对应什么，为什么它成立
3. 适用范围 —— 什么情况下能用、什么情况下**不能用**（最容易丢分的地方）
4. 一个最小例子 —— 把定义代进去走一遍
5. 一句小结 —— 这个考点在考卷上通常以什么形式出现

第 3 段是刻意要求的。少掉它，模型就只会照本宣科，学生一问边界就崩。
而且 `lecture` 阶段明确放宽了字数（400 字以内都可以）——
**这一轮讲不透，后面每一轮都在补债。**

讲完留一个**回忆式**问题（不动笔的那种），然后停下来等你答。

### 场景 B · 多人课堂（class）

同一节课，旁边还坐着三个水平不同的学生。他们会：
- 各自拿**不同量**的资料（见第三节）
- 各自踩**不同的坑**
- 从第 2 轮起**必须先回应前面某个人说过的话**

你要做的不是旁观，是**判断谁说得对**。三个人的发言里掺着真实的错误思路
（来自题库干扰项），而老师**不会提前公布答案** —— 谁对谁错得你自己吵出来。

### 场景 C · 答疑重讲（clarify）

这是整个设计里最关键的一个场景，因为它修的是一个具体毛病：

> 我说「没听懂」，它换了个说法又讲一遍，然后继续往下走。

修法是**状态**，不是提示词。说「没听懂」之后：
- 阶段切到 `clarify`，**三个学生全部安静**（不是提示词请求，是根本不调它们）
- 老师**必须**退回去重讲概念，换个说法、换个比喻、换个角度
- **绝对不许出题**。模型要是出了，代码把结尾那句换成理解确认
- 结尾必须给两个一键按钮：「还是没懂」/「懂了，继续」
- 兜底确认句里留出口：「说不清也没关系，说不清我就换个说法再讲一次」

少一个按钮这条链就断了 —— 用户会硬撑着说「懂了」，整个答疑阶段白跑。

### 场景 D · 练习与验证（practice）

说「懂了」之后，老师出一道**小题**，然后**停下来等你动手**。

这里有三条硬规则（写进 system prompt，不是「建议」）：

1. 你没交答案之前，**不许说出答案**，包括换个说法暗示
2. 你答错了，先给**最小提示**（只点一个方向），留一步让你自己走
3. 你答对之后，必须再出一道**同类新题**让你独立做 —— **答对不等于学会**

第 3 条是 ZPD 的验证环节：独立尝试 → 最小提示 → 再试一次 → 新题独立作答。
少了最后一步，「我懂了」永远只是一句感觉。

### 场景 E · 研讨课（debate）

不讲，直接抛一个开放问题让他们争。老师的任务是**维持张力**：
谁说得太顺就追问一个反例，谁说得太偏就把他拉回关键处，自己**不给结论**。

### 场景 F · AI 出题与判分

按考点生成练习题，自动判分，答错时 AI 讲评**你错在哪一步**（不是重做一遍）。

## 二、AI 功能的具体呈现方式

| AI 能力 | 在界面上长什么样 |
|---|---|
| 流式生成 | 老师的气泡逐字出现，末尾一个闪烁光标 |
| 工具调用 | 气泡下方一条虚线小胶囊：「陈老师 正在调用 look_up…」→「✓ 用了 look_up」 |
| 画函数图 | 黑板上一块图，曲线**从左到右描出来**（`pathLength` 归一化 + `stroke-dashoffset`） |
| 参数化曲线 | 图下方滑块，拖动时曲线实时变形，**坐标轴不动** |
| 写解题步骤 | 逐条错开落下，编号是渐变的琥珀色小方块 |
| 排公式 | 居中大字，`\frac` 渲染成真正的上下分式 |
| 圈重点 | 已有的某一块被琥珀色光晕包住，右上角一个「圈」标记 |
| 教学动作标签 | 老师气泡旁一个小胶囊：`focus` / `probing` / `telling` |
| 引导占比 | 侧栏三色条，显示这三种动作的比例 |
| 学生发言 | 逐字打字，串行队列（不互相打断），制造「正在说」的现场感 |
| 该你作答 | 输入区弹出一张蓝色发光的答题卡，带一键按钮和「跳过这题」 |
| 出题与判分 | 题目卡片 → 选项/输入 → 判分结果（对/错/**判不了**）→ AI 讲评 |
| 讲评失败 | 不弹错误，改成「你可以自己对照标准答案 X 看看是哪一步不一样」 |

### 三个刻意的呈现决策

**① 判分有三种结果，不是两种。**
`对` / `错` / **`判不了`**。第三种会明确说「这道题程序判不了分」并把标准答案
摊给你自己看。把「判不了」压成「错」，用户答对了却被告知错 ——
这是最伤信任的一种 bug。

**② 老师发言的第一行是教学动作标签，但用户看不到它。**
流式输出时就把 `(focus)` 剥掉，否则用户第一个 token 会看到 `(foc` 这种半截。
剥掉的标签进统计，变成一个数字：**这课到底在引导还是在念答案**。
好课以 focus / probing 为主；占比长期偏低说明老师在替你做题。

**③ 硬过滤的修改要如实上报。**
「这一轮本来要出题，被换成了理解确认 —— 他还没说听懂，不该往下推」
「这一轮是答疑，3 位同学已安静」

不报错让前端重试的理由：一次重试就是一次上游调用，花的是用户的钱；
而这几种越界都有语义等价的兜底。但**改了就要说**，不能静默。

## 三、agent 集群的分工与协作机制

### 3.1 分工：靠机制，不靠形容词

多智能体模拟的经典失败模式是**角色趋同**：只靠提示词写「你是个聪明学生」
「你基础不好」，模型会说出几乎一样的话——所有 agent 收敛到同一种腔调，
整个机制退化成噪音，比单角色还差。

所以差异来自三样**结构性**的东西：

**① 信息可见性递减** —— 给每个角色不同的**资料量**，而不是不同的性格描述

| 角色 | 定义 | 直观解释 | 适用范围 | 例题 | 考卷形式 | 关联考点 | 学情数据 |
|---|---|---|---|---|---|---|---|
| 陈老师 | 完整 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 林一鸣（优等生） | 完整 | ✓ | ✓ | ✓ | — | ✓ | — |
| 周雨桐（中等生） | 完整 | — | — | ✓ | — | — | — |
| 马小虎（后进生） | **只第一句** | — | — | — | — | — | — |

信息量不同 → 必然产生分歧。这个分歧是**结构性的**，不是表演出来的。

**② 工具白名单隔离** —— 学生**没有**「写完整解答」这个能力

```
老师：look_up  calc  draw_graph  highlight
      write_steps  write_latex  new_page  clear_board
      get_mistakes  query_weakness  pose_question

学生：look_up  calc  draw_graph  highlight
      recall_mistake  raise_hand  pass
```

学生**不该有能力「写完整解答」**——会画图不等于会写解法。
这条边界靠提示词约束不住（一旦学生拿到 `write_steps`，它就会开始写完整解法，
慢慢退化成第二个老师），只能靠工具表约束，而且写成了**模块级断言**：

```js
for (const t of STUDENT_TOOLS) {
  if (TEACHER_ONLY.includes(t)) throw new Error(`${t} 是老师专用，不该出现在学生白名单里`);
}
```

用 `Object.keys(TABLE).map(toSchema)` 的写法会让老师也拿到「举手/弃权」——
语义错误，而且会在断言「工具数量」的测试里静默破功。

**③ 错误来源必须真实** —— 后进生犯的错从**题库干扰项**里挖

每个考点带了若干条「学生真的会这么想」的错误思路。按角色序号索引，
一人分一个：

```js
const idx = Math.min(typeof a.level === 'number' ? a.level : 0, wrong.length - 1);
// 干扰项够多就一人一个；不够分才复用（min 夹住，别越界）
```

两条硬约束：
- **发给学生的干扰项里不能有正确答案** —— 只给「一个真实的错误思路」，
  谁对谁错让学生自己吵出来。老师也不许提前公布。
- **三个人都要会犯错。** 只让后进生犯错、优等生永远正确，看着就像陪读 ——
  没有张力，用户也不会有代入感。

| 角色 | 典型失误 |
|---|---|
| 林一鸣 | **结论下得太早**（不验边界条件） |
| 周雨桐 | **条件用错**（把成立前提记串） |
| 马小虎 | **概念混淆**（相邻概念当一回事） |

**④ 独立 agent，不是一次生成四段台词**

每个角色是**独立的一次调用 + 独立的记忆 + 独立的工具上下文**。

`Tools.execute(name, args, ctx)` 收到的必须是**包装过的** ctx：

```js
function studentToolCtx(ctx, roleKey, session) {
  var t = Object.create(ctx);
  t.levelMaterial = function () { return levelMaterial(ctx, session.kid, AGENTS[roleKey].level); };
  return t;
}
```

传原始 ctx 的话，工具内部拿不到裁剪函数，差异**直接失效** ——
提示词截了、工具没截，后进生照样查到了完整定义，四个人说话一模一样。

### 3.2 协作：谁在什么时候说话

**分层调度，能本地定的就不问模型：**

```
1. 有人举手            → 老师，直接定，不问模型
2. 还有人没开过口      → 按优先级让他开口，不问模型
3. 说到量了            → 结束，不问模型
4. 都不满足            → 才调一次调度器（返回 {"next": "agent_id" | "END"}）
5. 调度器挂了          → 兜底轮转，且不连着同一个人
```

**成本控制：**

| 手段 | 效果 |
|---|---|
| 首轮 `Promise.all` 并发 | 三个学生的墙钟时间 = 一次调用 |
| 后续串行 | 要看到别人的话才能接话 |
| 每个角色 loop 上限 2–3 步 | 不会无限调工具 |
| `clarify` 阶段**根本不调**学生 | 既省 token，又天然保证「其他人该安静」 |
| 调度器只在歧义回合调用 | 一场课最多 2–3 次 |

**记忆：只记自己的 + 吸收点名**

每个角色一份记忆，去重、上限 4 条。老师点评里出现「林一鸣」，
那句话就自动进林一鸣的记忆，下一轮他开口时能看到「老师点评到我：……」。
实现就是按句号切分后按名字匹配。

### 3.3 协作的**关键**：不让用户当观众

四个 agent 聊得热闹、用户在旁边看 —— 那不是学习，是一档节目。

判断标准很简单：**整场下来有没有任何一步要求用户动手？**

所以调度流程里插了一个 `await`，返回一个**不会自己 resolve 的 Promise**：

```js
function askUser(session, hooks, spec) {
  const payload = { prompt: spec.prompt, placeholder: spec.placeholder, phase: spec.phase };

  // ⚠️ emit 必须在 onAsk 分支之前！写在 Promise executor 里面的话，
  //    onAsk 直通会提前 return，UI 永远收不到「该你了」事件（真踩过）
  emit(hooks, { type: 'ask', spec: payload });

  if (hooks && typeof hooks.onAsk === 'function') {
    return Promise.resolve(hooks.onAsk(payload));        // 测试 / 无人值守直通
  }
  return new Promise(function (resolve) {
    session.awaiting = { prompt: payload.prompt, resolve: resolve };
  });
}
```

挂起是**纯本地等待，不花 token**，收益却是全部。四个必须处理的坑：

1. **`emit` 要在两条分支之前**。这是最阴的一个 —— 直通路径测试全绿，
   只有真机上 UI 收不到事件。
2. **`awaiting` 不能进存档**。Promise 序列化会丢 `resolve`，
   从 localStorage 读回来的 `awaiting` 是个**按了没反应的死框**。
   用一个内存标记（`LIVE` 这个 `WeakSet`）区分「正在跑的会话」和「读回来的死数据」。
3. **等待期间要关掉其它输入入口**（插话）。否则老师同时被两条线拉扯，
   而且用户此刻该做的是交答案，不是闲聊。
4. **要能跳过**。`skipAnswer` 让流程照常继续，但后续提示词里明确写
   「他跳过了，别追问」。

### 3.4 门禁：用「现在是否在跑」，不能用「是否有内容」

真踩过的：

```js
var live = !!(session && session.turns && session.turns.length);   // 「已经有发言内容」
var canInterject = live && isLive(session) && !session.awaiting;   // ✗
```

`startClass` 建 session 时 `turns: []`，紧接着就渲染页面 ——
于是 `live === false`，**输入框一渲染出来就是禁用的，整节课都点不了**。
而收尾时又无条件 `disabled = false`，留下一个点了只弹「这一节已经中断了」的框。
两头都错。

正解是拿「有没有一节正在跑的课」当唯一条件，并且把可用状态收进**一个函数**：

```js
function canInterject(session) {
  return isLive(session) && !(session && session.awaiting);
}
function setInterject(session) {          // 渲染 / 抛题 / 交答案 / 收尾 四处共用
  var on = canInterject(session);
  /* 统一改 disabled + placeholder */
  return on;
}
```

三条经验：
1. 别让同一套 UI 状态散落在 4 个地方手写 `disabled` —— 一定会漏掉一个。
2. 禁用了就要**说清为什么**（placeholder 或旁注写「先把上面那道题交了」）。
3. **页面渲染那一刻的状态最容易被写错**，因为初始化时的数据往往是空的。
   凡是「渲染时算一次」的门禁，都要问一句：这个谓词在**空初始值**下会得到什么？

## 四、趣味性的交互设计

趣味性不是加个 emoji 或撒花动画。这里的趣味来自**张力**和**现场感**：

| 设计 | 为什么好玩 |
|---|---|
| 三个水平不同的同学会**说错话** | 用户有了「我比马小虎强」的参照，也有了「等等，林一鸣是不是漏了条件」的怀疑 |
| 从第 2 轮起必须**互相回应** | 形成真正的对话，而不是三段独白 |
| 老师**不提前公布答案** | 谁对谁错得用户自己判断 —— 这是参与，不是接受 |
| 黑板是**一串动作**，不是一张图 | 步骤逐条落下、曲线一笔描出、重点被圈住，有「老师在写」的现场感 |
| 曲线**能拖** | 拖一下参数，立刻看见曲线怎么变 —— 这是自己动手，不是看别人画 |
| 一键「还是没懂」/「懂了，继续」 | 不用打字就能推进，降低表达门槛。少一个按钮这条链就断了 |
| 逐字打字 + 头像呼吸圈 | 等待变短，有「正在说」的现场感。比一个转圈 loader 好得多 |
| 引导占比仪表 | 把「这课到底在引导还是在念答案」变成一个数字，当场就能看出来 |
| 错题角标在考点树上 | 一眼看见自己的薄弱处，点进去就能开一节针对它的课 |
| 「跳过这题」 | 卡住了不必硬撑，老师会换个更小的题 —— 不让人卡死在原地 |

### 两个被刻意避开的「伪趣味」

- **不做撒花/音效/积分**。这些和学会无关，而且会稀释注意力。
- **不做「AI 夸你」**。system prompt 里明确禁止「很好的问题」「这是个好思路」
  这类开场白 —— 直接说事。虚假的鼓励会让人不再相信真实的评价。

## 五、关键功能模块与预期效果

| 模块 | 文件 | 做什么 | 预期效果 |
|---|---|---|---|
| 模型通道 | `llm.js` | SSE 解析、**按 index 聚合分片 tool_calls**、三级降级、错误分类 | 换个 OpenAI 兼容网关也能用；401/402/429/超时/断网各说各的话 |
| 工具集 | `tools.js` | 工具表 + 角色白名单 + **无 eval** 的表达式求值器 + 黑板动作族 | 学生没有写解答的能力；参数作用域不泄漏；`-x^2 = -(x^2)` |
| 考点库 | `curriculum.js` | 14 个考点的五段内容 + 18 道题 + 33 条干扰项 + 按角色裁剪 | 老师讲得比课本更针对；学生资料量递减 |
| 判分与清洗 | `judge.js` | 归一化、数值比对、AI 出题的两道防线 | 判不了分就明说，不硬判；坏题一道都不留 |
| Agent 内核 | `agent.js` | 提示词 + 阶段状态机 + 意图分类 + 硬过滤 + 动作标签统计 | 「没听懂」之后真的会重讲、真的不出题 |
| 集群编排 | `classroom.js` | 调度、记忆、挂起唤醒、成本控制、门禁 | 每一轮都停下来等你；用户不是观众 |
| 本地档案 | `store.js` | 作答记录 → 薄弱点排序 → **自然语言摘要** | 提示词里带上真实状态，而不是泛泛而谈 |
| 公式渲染 | `latex.js` | LaTeX 子集 → HTML，**不引 KaTeX** | 离线可用、双击可开；`\frac` 是真分式 |
| 界面 | `app.js` + CSS | 对话流、黑板、答题卡、练习、错题本 | 深色单主题，曲线能拖，步骤逐条落 |
| 服务端 | `server.js` | 静态托管 + 转发 + **密钥隔离** + 路径穿越防护 | 浏览器里一个密钥字符都没有 |

### 可验证的预期效果

这些不是形容词，是测试里钉住的：

| 效果 | 怎么验的 |
