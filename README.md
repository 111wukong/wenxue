# 问学 · 多智能体 AI 课堂

> 一个老师 + 三个水平不同的学生，围着一个考点把课上一遍。
> 每一轮结束都会停下来等你作答 —— 你不是观众。

零依赖（没有 `node_modules`，没有构建步骤），一个 Node 进程同时干两件事：
托管前端、把模型请求转发给 DeepSeek。**API Key 只在服务端进程内存里，
浏览器里一个字符都没有。**

```bash
cp .env.example .env      # 填 DEEPSEEK_API_KEY
node server.js            # → http://127.0.0.1:5188
```

---

## 它解决的是哪个具体毛病

绝大多数「AI 学习工具」的病根不是模型弱，是**提示词里只有静态知识、没有用户状态**。

写「你是考研数学老师」，任何模型都只能讲通用内容。
写「他罗尔定理错了 3 次，最近三次是错对错，上次错在漏了可导性」——
它才会针对性地讲。

所以这个项目里有三样东西是刻意做的：

| 做法 | 为什么 |
|---|---|
| 学习档案实时注入提示词 | 从本机作答记录算出自然语言摘要，每轮都带上 |
| 教学阶段由**代码**持有 | 模型除了对话历史不持有任何状态，每轮把全部规则平铺给它，它会按惯性走错 |
| 每轮挂起等作答 | 整场下来**每一步都要求用户动手**，否则那是节目不是课 |

## 四个角色，靠机制区分而不是靠形容词

这是多智能体最容易做砸的地方：写「你是个聪明学生」「你基础不好」，
模型会说出几乎一样的话——所有 agent 收敛到同一种腔调，机制退化成噪音。

所以差异化靠三样**结构性**的东西：

| 角色 | 拿到的资料 | 典型失误 |
|---|---|---|
| 陈老师 | 严格表述 + 直观解释 + 适用范围 + 例题 + 考卷形式 + 学情数据 | —— |
| 林一鸣（优等生） | 完整正文 + 例题 + 关联考点 | **结论下得太早**（不验边界条件） |
| 周雨桐（中等生） | 正文 + 例题 | **条件用错**（把成立前提记串） |
| 马小虎（后进生） | **只有第一句定义** | **概念混淆**（相邻概念当一回事） |

关键在**第三列**：只截 system 提示是没用的，模型会自己脑补出完整知识。
必须让**工具的数据源本身也按角色裁剪**——后进生调 `look_up` 查到的定义
真的只有一句话。这叫结构性无知。

第二层是**工具白名单**：学生**没有** `write_steps` / `write_latex`
（写完整解答的能力）。会画图不等于会写解法，这条边界靠提示词约束不住，
只能靠工具表约束，而且写成了模块级断言 —— 见 `public/js/tools.js` 末尾。

第三层是**错法要真实**：后进生的困惑来自题库干扰项，不是模型编的。

## 三层架构

```
llm.js        模型通道：探测、流式对话、tool_calls 解析、降级
tools.js      工具集：schema + 执行器 + 领域工具（黑板动作族 / 计算 / 查资料）
agent.js      内核循环：prompt 构建、loop、compaction、阶段状态机
classroom.js  集群编排：调度、记忆、挂起、成本控制
```

**降级链三层，缺一层换个模型就整个不能用：**

1. 原生 `tools` 参数
2. 文本工具协议（```tool 围栏代码块）
3. 纯文本回答

**工具结果回灌的两种形状**（很容易错）：

- 原生调用 → `{role:'assistant', tool_calls}` + `{role:'tool', tool_call_id}`
- 文本协议 → `{role:'assistant', content:'```tool…```'}` + `{role:'user', content:'【工具结果】…'}`
  （**不能用 `tool` role** —— 没有合法的 `tool_call_id` 对应）

## 教学阶段状态机

模型除了对话历史之外不持有任何状态。每轮把全部规则平铺给它，它会按
「每轮要留一道题」这种惯性继续走 —— 即使这一轮的情况已经完全相反。

所以**阶段由代码持有**，提示词只描述**当前这一个状态**该干什么：

| 阶段 | 进入条件 | 谁能说话 | 结尾留什么 |
|---|---|---|---|
| `lecture` | 第 1 轮 | 老师 + 同学 | 回忆式问题（不动笔） |
| `explain` | 常规讲授 | 老师 + 同学 | 回忆式问题 |
| `clarify` | 他说「没听懂」 | **只有老师** | **理解确认（禁止出题）** |
| `practice` | 他说「懂了」 | 老师 + 同学 | 一道小题 |
| `discuss` | 研讨模式 | 老师 + 同学 | 开放问题 |

意图分类的**顺序就是语义**：

```js
if (CONFUSED_RE.test(s))   return 'confused';    // ← 必须排在前面
if (UNDERSTOOD_RE.test(s)) return 'understood';
if (QUESTION_RE.test(s))   return 'question';
return 'other';
```

「听不懂」「没听懂」里都带一个「懂」字。反过来判的话，
「我还是没听懂」会被归成「听懂了」，下一轮直接甩一道题出来 ——
那正是要修的毛病本身。这条有回归断言钉着。

**提示词是请求，硬过滤才是保证。** 模型输出之后要兜：

- `clarify` 阶段把非老师角色的发言全部摘掉（而且**根本不调**它们 —— 省 token）
- `clarify` 阶段结尾若是算题，换成理解确认句
- `clarify` 阶段没有结尾问题就补一个

三种越界都**如实上报**给前端，用户能看到「这一轮本来要出题，被换成了确认」。

## 黑板是一串动作，不是一张图

| 动作 | 给谁 | 效果 |
|---|---|---|
| `draw_graph` | 老师 + 学生 | 画函数图像，曲线从左到右描出来，**参数可拖** |
| `write_steps` | 只有老师 | 解题步骤（上限 8 条），逐条错开落下 |
| `write_latex` | 只有老师 | 排公式，`$` / `$$` 定界符自动剥掉 |
| `highlight` | 老师 + 学生 | 圈出已有某一块（按**文字**匹配，不是坐标） |
| `new_page` | 只有老师 | 翻页，**旧内容保留** |
| `clear_board` | 只有老师 | 擦黑板，之前作废 |

所有动作返回**同一个形状** `{type:'board', item:{kind, …}}`，
渲染层只认 `kind`。`highlight` 是打在已有块上的光，**不占黑板块数的号**。

拖参数时坐标轴是**预先算好并钉死**的：让每个参数各取遍 min / max 端点，
把结果并起来求包络。不钉的话坐标轴会跟着参数一起缩放，整张图随手指抖，
反而看不出参数到底改变了什么。

## 成本

不让所有角色都独立调模型，也不每回合都问一次调度器：

- **首轮并发**（`Promise.all`）→ 墙钟时间等于一次调用
- 后续串行（要看到别人的话才能接话）
- 发言调度先走**本地规则**（有人举手 → 老师；还有人没开口 → 让他开口；说到量了 → 结束），
  只在真正歧义时才调一次调度器
- 每个角色的 agent loop 步数上限 2–3

一场课的调用次数（UI 上直接标出来了，不让你猜）：

| 模式 | 轮数 | 大概调用次数 |
|---|---|---|
| 一对一讲透 | 4 | ≈ 8 |
| 多人课堂 | 3 | ≈ 16 |
| 研讨课 | 3 | ≈ 16 |

## 测试

```bash
npm test          # 三个套件，2 秒，464 条断言
node scripts/smoke-real.mjs   # 对真的 DeepSeek 打一次
```

**不依赖真实模型。** 用 Node 起一个 OpenAI 兼容的假上游，手动构造流式 SSE，
覆盖全部路径 —— 而且确定性，真模型做不到这一点。

三类断言值得单独说：

**① 最要紧的一条不是「函数返回了 ok」，而是「服务端真的收到了凭据」。**
mock 会把每个请求的 `Authorization` 头记下来，直接断言它。
只断言返回值的话，即使凭据没发出去、只要 mock 不校验，测试照样绿。

**② 不变量 + 畸形输入扫描。** 清洗函数守不住单点断言，要写
「只要产出了题，它就一定是可判的」，再喂一组全是坏形状的输入。
而且还要**手工写一个错误实现**，确认不变量真能抓住它 ——
一个永远为绿的检查比没有检查更糟。

**③ 回归断言钉住每个踩过的坑**（下面这些全部来自实际踩坑）：

- `-x^2` 必须是 `-(x^2)`，`x^2^3` 必须右结合
- `x(x-1)` 是隐式乘法，**不是**函数调用 `x(...)`
- 参数作用域只采纳声明过的名字（否则一个叫 `pi` 的 key 能顶掉内置常数）
- 判不了分的题返回 `gradable:false` + `correct:null`，**不能压成「错」**
- `clarify` + 空输入不许自己滑进练习
- 「求极限有哪些方法？」**不算**算题（正则误杀会把好问题换成兜底句）
- 黑板增量动画的记账口径必须和渲染口径一致，`isNaN` 时 fallback 是 `drawn.length` **不是 0**
- 门禁条件用「现在是否在跑」，不能用「是否有内容」
- 中文输入法组合期回车不能提交
- `app.js` 的模块图必须能链接起来（`node --check` 只查语法，链接失败是整页白屏）
- 拖参数前要摘掉入场动画的类，否则每拖一下重播一次描线

## 安全

| 事项 | 做法 |
|---|---|
| API Key | 只在服务端进程内存；`/api/health` 只回「配没配」和**来源**，连脱敏前缀都不回 |
| 路径穿越 | 静态服务 `resolve` 之后必须确认仍在 `public/` 里 |
| 表达式求值 | 自己写递归下降 parser，**不用 `eval` / `new Function`** —— 表达式来自模型输出 |
| XSS | 先整体转义，再把 `$…$` 当公式渲染；不认识的宏原样保留 |
| 上游报错 | 读出正文再转发（余额不足 / 模型名错 / 参数不对 都在里面） |
| 计费 | 客户端断开时 `abort` 上游，用户关掉页面不会继续烧钱 |

### ★ `.env` 和环境变量谁说了算

**凭据类（`*_API_KEY` / `*_TOKEN` / `*_SECRET` / `*_PASSWORD`）：`.env` 为准。**

这条和多数实现相反，是刻意的。真踩过：本机 `~/.zshrc` 里导出着一个旧 key，
于是明明把新 key 写进了 `.env`，服务端却全程在用旧的 ——
健康检查报「已配置」，每条消息却 401，而报错里只有上游那句
`your api key: ****b605 is invalid`，看上去像 key 本身失效，根本查不到「用错了哪一把」。

**其余（`PORT` / `HOST` / 超时）：环境变量为准**（常规做法），
这样 `PORT=5199 node server.js` 能用。

两边不一致时，启动日志会大声说出来。想临时换 key：`WENXUE_ENV_WINS=1 node server.js`。

## 界面

深色单主题。不是偷懒——课堂场景里黑板、公式、曲线是主角，
深色底能让它们自己发光，亮色底会把它们压平。

- 品牌栏 / 考点树（带错题角标）/ 模式选择 / 学习档案 / 工具清单
- 中间：课堂（对话流 + 答题卡）/ 练习（AI 出题 + 判分 + 讲评）/ 错题本
- 右侧：黑板

细节：曲线用 `pathLength="1"` 归一化描线（不去量路径长度）；
步骤逐条错开落下；学生发言逐字打字（串行队列，不互相打断）；
引导占比用三色条显示 focus / probing / telling 的比例。
`prefers-reduced-motion` 里**同时**清掉 `stroke-dasharray` ——
少那一句，曲线会整条消失。

## 已知边界

- 判分只覆盖**选择题**和**纯数值填空题**。答案是「至少 1 个」这类文字的题，
  程序会**明确说判不了**并把标准答案摊给你自己看，而不是硬判。
  硬判有可能把你对的答案判成错的 —— 那比不判更糟。
- AI 出题的清洗是**从严**的：含根号、字母、区间、集合的答案一律丢掉。
  宁可少给，不给坏的。
- 14 个考点（高等数学 7 / 线性代数 3 / 概率论 4）是为了把机制跑通而准备的样本。
  换学科只需要改 `curriculum.js`，其它模块不用动。
- 没有持久化后端：档案存在浏览器 `localStorage` 里，换台机器就没了。
